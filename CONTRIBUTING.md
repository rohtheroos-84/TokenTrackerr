# Contributing to TokenTrackerr

Thank you for your interest in contributing to TokenTrackerr! This is an educational web development project, and we welcome contributions that help improve the code quality, design, or learning value.

## Project Goals

This project aims to:
- Demonstrate modern web development techniques
- Provide a learning resource for HTML, CSS, and JavaScript
- Showcase responsive design and UI/UX principles
- Serve as a portfolio piece

## Types of Contributions Welcome

### Code Improvements
- Bug fixes
- Performance optimizations
- Code refactoring for better readability
- Accessibility enhancements
- Cross-browser compatibility fixes

### Design Enhancements
- UI/UX improvements
- Responsive design fixes
- Animation and transition improvements
- Color scheme and theme enhancements

### Documentation
- README improvements
- Code comments and documentation
- Tutorial content
- Setup instructions

### Features (Educational Focus)
- New UI components for learning
- Interactive elements
- Chart/visualization improvements
- Additional demonstration pages

## How to Contribute

### 1. Fork the Repository
Click the "Fork" button at the top right of the repository page.

### 2. Clone Your Fork
```bash
git clone https://github.com/rohtheroos-84/TokenTrackerr.git
cd TokenTrackerr
```

### 3. Create a Branch
```bash
git checkout -b feature/your-feature-name
# or
git checkout -b fix/your-bug-fix
```

Branch naming conventions:
- `feature/` - New features or enhancements
- `fix/` - Bug fixes
- `docs/` - Documentation updates
- `style/` - CSS/styling changes
- `refactor/` - Code refactoring

### 4. Make Your Changes
- Write clean, readable code
- Follow existing code style and conventions
- Add comments where necessary
- Test your changes in multiple browsers
- Ensure responsive design works on different screen sizes

### 5. Test Your Changes
Before submitting:
- [ ] Test in Chrome, Firefox, Safari, and Edge
- [ ] Test on mobile devices or browser dev tools
- [ ] Verify dark mode works correctly
- [ ] Check all links and navigation
- [ ] Ensure no console errors

### 6. Commit Your Changes
```bash
git add .
git commit -m "Brief description of your changes"
```

Commit message guidelines:
- Use present tense ("Add feature" not "Added feature")
- Be descriptive but concise
- Reference issues if applicable (#123)

### 7. Push to Your Fork
```bash
git push origin feature/your-feature-name
```

### 8. Create a Pull Request
1. Go to the original repository
2. Click "New Pull Request"
3. Select your fork and branch
4. Fill in the PR template with:
   - Description of changes
   - Screenshots (for UI changes)
   - Testing performed
   - Any breaking changes

## Code Style Guidelines

### HTML
- Use semantic HTML5 elements
- Maintain proper indentation (2 spaces)
- Add descriptive comments for sections
- Use meaningful class names

### CSS
- Follow existing naming conventions
- Keep specificity low
- Use CSS variables for colors and common values
- Group related styles together
- Add comments for complex styles

### JavaScript
- Use descriptive variable and function names
- Add comments for complex logic
- Use modern ES6+ syntax
- Keep functions small and focused
- Avoid global variables

## Reporting Bugs

When reporting bugs, please include:
- Browser and version
- Operating system
- Steps to reproduce
- Expected behavior
- Actual behavior
- Screenshots if applicable

## Suggesting Features

For feature suggestions:
- Explain the use case
- Describe the expected behavior
- Consider educational value
- Keep scope appropriate for a static demo

## Important Notes

### What NOT to Contribute
- Real API integrations (this is a static demo)
- Backend functionality (front-end only project)
- User authentication systems
- Database connections
- Changes that remove disclaimer notices

### Keep in Mind
- This is an **educational/demo project**
- All data should remain **fictional**
- Maintain the **disclaimer notices**
- Focus on **learning and demonstration**

## Code of Conduct

### Our Standards
- Be respectful and inclusive
- Provide constructive feedback
- Focus on what's best for the project
- Show empathy towards other contributors

### Unacceptable Behavior
- Harassment or discriminatory language
- Trolling or insulting comments
- Personal or political attacks
- Publishing others' private information
